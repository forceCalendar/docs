forceCalendar separates calendar logic, presentation and platform persistence. Choose the layer you need:

| Layer | Current documented version | What it provides |
| --- | --- | --- |
| [Core](/docs/core) | 2.5.6 | Headless events, recurrence, search, timezone utilities and ICS |
| [Interface](/docs/interface) | 1.9.0 | Month/week/day Web Components, snapshots, selection and event editing |
| [React](/docs/adapters/react) | 0.3.1 | Typed props, callbacks, refs and client-side registration |
| [Vue](/docs/adapters/vue) | 0.3.1 | Typed props, emits, template refs and client-side registration |
| [Salesforce](/docs/salesforce) | 0.3 beta | LWC, Apex persistence and optional Reader/Editor permission sets |
| [Agent calendars](/docs/agent) | Private pre-release | Durable shared calendars and scoped agent tools; availability is limited |

Versions and verification boundaries are summarized in [What's new](/docs/whats-new). The npm packages and the Salesforce beta have different release processes.

## Design and boundaries

**Headless Core.** Core ships as ESM with no runtime package dependencies. Calendar computation works without a DOM; browser download helpers and optional Workers still need the corresponding host APIs. No dependencies reduces dependency exposure, but does not eliminate security risk.

**Web Components.** Interface supplies `<forcecal-main>` and `<forcecal-event-form>` with Shadow DOM. Applications own persistence and server authorization. A browser event notification is not proof that a remote save succeeded.

**Salesforce support.** The LWC requires Lightning Web Security (LWS). Legacy Lightning Locker does not support the third-party custom elements used by this integration. Manual DOM insertion does not bypass that requirement.

**Dates are an integration contract.** Timed events, inclusive all-day civil dates, visible-range ends and provider-exclusive end dates are different concepts. Read the [date guidance](/docs/migration#dates-and-timezones) before adapting an external calendar. The Interface grid and visible range currently use the browser's local timezone; setting `timezone` does not turn them into an arbitrary-zone grid.

**Recurrence is bounded.** Core implements RFC 5545 recurrence features, with explicit resource limits and known edge cases. Built-in recurring-event mutation is disabled until a series/occurrence scope workflow exists. See [recurrence](/docs/core/recurrence) for the current cross-host DST limitation.

**Verify your environment.** Shipped tests cover specific paths, not every browser, Salesforce org, assistive technology or external provider. See [security](/docs/security) and the component guides for the remaining boundaries.
